# Obsidian 에서 쓴 글을 이 사이트에 공개하기

이 저장소는 **공개용 창구**이고, 평소 노트는 비공개 Git 의 Obsidian 보관함(vault)에 둡니다.
공개할 글만 이 저장소의 `content/posts/`(글) 또는 `content/notes/`(짧은 노트)로 옮깁니다.

> 아래 "되는 것 / 안 되는 것"은 실제로 빌드해서 확인한 결과입니다.

## 1. 공개 방식 고르기

| 방식 | 방법 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 복사 (권장 시작점)** | 공개할 글만 보관함에서 `content/posts/<글>/` 로 복사하고 이 저장소에서 커밋 | 가장 단순. 공개 저장소만으로 빌드되므로 GitHub/Cloudflare 가 비공개 저장소에 접근할 필요가 없음 | 복사본이 두 개. 수정은 보관함에서 하고 다시 복사해야 함 |
| B. 폴더 연결 | 보관함 안에 `content/posts` 로 연결되는 폴더(심볼릭 링크, Windows 는 정션 `mklink /J`)를 만들고 보관함의 `.gitignore` 에 그 폴더를 추가 | 복사 없이 Obsidian 에서 바로 수정 | 링크/정션을 Obsidian 이 잘 다루는지 환경별로 시험 필요. 실수로 비공개 노트를 그 폴더에 두면 공개될 수 있음 |

비공개 보관함을 서브모듈이나 Actions 로 끌어오는 방식은 토큰 관리가 필요해서 권하지 않습니다.

어느 방식이든 **공개 폴더에 있는 글만 공개**됩니다. 보관함 전체를 공개 폴더로 쓰지 마세요.

## 2. Obsidian 설정 (설정 → 파일 및 링크)

| 설정 | 값 | 이유 |
| --- | --- | --- |
| Use [[Wikilinks]] (위키링크 사용) | **끔** | 위키링크는 사이트에서 그대로 글자로 나옴 |
| New link format (새 링크 형식) | Relative path to file (파일 기준 상대 경로) | 마크다운 링크가 상대 경로로 만들어짐 |
| Default location for new attachments (새 첨부 파일 위치) | Same folder as current file (현재 파일과 같은 폴더) | 이미지가 글과 같은 폴더에 있어야 `![](pic.png)` 가 동작 |
| Automatically update internal links | 켬 | 파일 이름을 바꿔도 링크 유지 |

이 설정은 보관함 전체에 적용되므로, 공개할 글에는 위키링크를 쓰지 않는 습관이 필요합니다.

공개 글 하나는 폴더로 만드는 것을 권합니다.

```
content/posts/my-post/
  index.md        ← 글 본문 (주소: /posts/my-post/)
  cover.png       ← 같은 폴더의 이미지
```

## 3. 프런트매터

### 글 (`content/posts/**/*.md`, `.mdx`)

```yaml
---
title: 글 제목 (60자 이내)
description: 한두 문장 요약 (권장 50~160자)
publishDate: 2026-10-09
updatedDate: 2026-10-09
tags:
  - obsidian
  - astro
draft: false
---
```

| 속성 | 필수 | 설명 |
| --- | --- | --- |
| `title` | O | **60자 이내** (넘으면 빌드 실패) |
| `description` | O | 문자열. 길이 제한은 없지만 검색/공유용으로 50~160자 권장 |
| `publishDate` | O | `2026-10-09` 처럼 날짜만, 또는 날짜+시간. 따옴표 유무와 관계없이 동작 |
| `updatedDate` | | 있으면 이 날짜로 정렬 |
| `tags` | | 소문자로 바뀌고 중복은 제거됨. 공백이 있으면 주소에도 공백이 들어가므로 `my-tag` 처럼 하이픈 권장 |
| `draft` | | `true` 면 **운영 빌드에서 제외** (개발 서버에서는 보임) |
| `pinned` | | 홈/목록 상단 고정 (최대 3개) |
| `coverImage` | | `src: ./cover.png`, `alt: 설명` 둘 다 필요 |
| `ogImage` | | 공유 이미지 경로. 없으면 자동 생성 |

Obsidian 이 붙이는 `aliases`, `created`, `cssclasses` 같은 **다른 속성은 에러 없이 무시**됩니다.

### 노트 (`content/notes/*.md`) — ⚠️ 날짜 형식 주의

```yaml
---
title: 짧은 노트 제목
publishDate: "2026-10-09T10:00:00+09:00"
---
```

노트의 `publishDate` 는 **따옴표로 감싼 ISO 형식에 시간대(`Z` 또는 `+09:00`)가 있어야** 합니다.

| 값 | 결과 |
| --- | --- |
| `"2026-10-09T10:00:00+09:00"` | 됨 |
| `"2026-10-09T01:00:00Z"` | 됨 |
| `2026-10-09T10:00:00+09:00` (따옴표 없음) | **실패** (YAML 이 날짜 객체로 읽음) |
| `"2026-10-09T10:00"` (시간대 없음) | **실패** |
| `"2026-10-09"` (날짜만) | **실패** |

Obsidian 의 "날짜 및 시간" 속성은 따옴표와 시간대가 없는 값을 만드므로 **노트에는 쓰지 말고 직접 입력**하세요.
(글은 `publishDate` 가 날짜만이어도 됩니다.)

## 4. 본문에서 되는 것 / 안 되는 것

### 됨

| 문법 | 비고 |
| --- | --- |
| `![](pic.png)`, `![](./pic.png)`, `![](pic%20two.png)` | 같은 폴더 이미지. 자동으로 최적화(webp). Obsidian 이 만드는 형식(앞에 `./` 없음, 공백은 `%20`) 그대로 동작 |
| `[설명](#제목)` 같은 글 안 앵커 | 한글 제목도 동작 |
| 일반 링크 `[글](../다른-글/)` | 글 주소 형태의 **상대 경로** |
| 각주 `[^1]`, 코드 블록, 표 | |
| `:::note[제목]` … `:::` | Cactus 의 admonition (note, tip, important, warning, caution) |
| `.obsidian/` 같은 숨김 폴더 | 글로 잡히지 않음 (공개 폴더 안에 있어도 무시) |

### 안 됨

| 문법 | 사이트에서의 결과 | 대신 |
| --- | --- | --- |
| `[[위키링크]]`, `[[글\|별칭]]` | 대괄호 글자 그대로 출력 | 일반 마크다운 링크 |
| `![[pic.png]]` (임베드) | `![[pic.png]]` 글자 그대로 | `![](pic.png)` |
| `> [!note] 제목` (Obsidian 콜아웃) | 일반 인용문에 `[!note]` 글자가 노출 | `:::note[제목]` |
| **`[글](../다른-글.md)` (파일 링크)** | **링크가 `../다른-글.md` 로 남아 404** | 아래 참고 |
| `/posts/다른-글/` (루트 기준 주소) | GitHub Pages(`/my_small_recipe_book/` 하위 경로)에서 깨짐 | 상대 경로 `../다른-글/` |

### 글끼리 링크하기

Obsidian 의 일반 링크 모드는 `../다른-글/index.md` 처럼 **파일 경로**를 만들지만, 사이트에는 그 파일이 없습니다.
(이 저장소가 예전에 쓰던 상대 링크 변환 플러그인을 원본 v8 이 없앴습니다.)

지금은 글끼리 링크를 **글 주소 형태의 상대 경로**로 직접 씁니다.

```md
[다른 글](../다른-글/)
```

현재 글이 `/posts/내-글/` 이면 `../다른-글/` 은 `/posts/다른-글/` 이 되어 두 배포 환경에서 모두 동작합니다.
대신 Obsidian 안에서는 이 링크를 눌러도 파일로 이동하지 않습니다.

Obsidian 에서도 클릭되고 사이트에서도 동작하게 하려면 `.md` 파일 링크를 주소로 바꾸는 작은 플러그인을 추가해야 합니다
(직접 작성하는 코드가 늘고 원본 업데이트 때 `astro.config.ts` 한 줄이 충돌 대상이 됩니다).

## 5. 공개 흐름

1. Obsidian 에서 글을 쓰고 `draft: true` 로 시작
2. 공개할 폴더를 `content/posts/<글>/` 에 복사 (방식 B 는 이미 그 위치)
3. 로컬에서 확인: `pnpm dev` (draft 글도 보임) 또는 `pnpm build`
4. `dev` 브랜치에 푸시 → 테스트 배포(GitHub Pages 미리보기, Cloudflare 미리보기) 확인
5. `draft: false` 로 바꾸고 `dev` → `main` 병합 → 운영 배포

공개 전 체크: 제목 60자 이내인지, 이미지가 같은 폴더에 있는지, 위키링크/콜아웃/`.md` 링크가 남아 있지 않은지,
비공개 정보(내부 링크, 개인 메모)가 없는지.

검사용 명령 (남은 Obsidian 문법 찾기):

```sh
grep -rnIE '\[\[|!\[\[|\[!(note|tip|warning|info)|\]\([^)]*\.mdx?\)' content/posts
```

## 6. 템플릿

Obsidian 코어 플러그인 "템플릿" 을 켜고 템플릿 폴더에 아래 파일을 만들어 두세요.

`글 템플릿.md`

```md
---
title:
description:
publishDate: {{date:YYYY-MM-DD}}
tags: []
draft: true
---

```

`노트 템플릿.md` (날짜 형식 때문에 시간대까지 직접 쓰게 되어 있음)

```md
---
title:
publishDate: "{{date:YYYY-MM-DD}}T{{time:HH:mm}}:00+09:00"
---

```

(VS Code 에서는 `.vscode/post.code-snippets` 의 `frontmatter-post` 로 같은 틀을 넣을 수 있습니다.)
